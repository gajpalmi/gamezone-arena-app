GAMEZONE ARENA में अभी Category system पूरी तरह functional नहीं है।

CURRENT PROBLEMS:

1. Add Business में Category button दिखाई देता है, लेकिन tap करने पर कोई category list नहीं आती।
2. Add Product में Category दिखाई देता है, लेकिन categories नहीं आतीं।
3. Add Service में Category दिखाई देता है, लेकिन categories नहीं आतीं।
4. Post a Job में Category दिखाई देता है, लेकिन categories नहीं आतीं।
5. Find Jobs / Find Workers में Category filter मौजूद है लेकिन category options खाली हैं।
6. Category पर tap करने के बाद user को वास्तविक category list दिखाई नहीं देती।
7. Category चुनने के बाद "Choose/Select" action नहीं मिलता।
8. Search field में typing करते ही search/navigation trigger हो रहा है। ऐसा नहीं होना चाहिए।
9. Search तभी execute हो जब user explicitly Search करे या search submit करे।
10. Category system के लिए एक reliable central data source/loader चाहिए।

IMPORTANT:
यह केवल button/UI fix नहीं है।
Category data → database/static source → loader → state → selector → selected value → save → edit → preview → discovery/filter पूरा flow ठीक करें।

Existing Business, Products, Services, Jobs, Ludo, Games, Profile, Settings, Supabase, Clerk और security/RLS को न हटाएं और न तोड़ें।

कोई EAS build/APK/AAB/deployment/paid operation शुरू न करें।

1. CENTRAL CATEGORY SYSTEM

एक centralized category system बनाएं/reuse करें ताकि सभी screens अलग-अलग hardcoded/empty category arrays पर निर्भर न हों।

एक ही reliable category source हो।

Architecture ideally:

Category Data Source
→ "useCategories()" / existing equivalent
→ cached category list
→ CategoryPicker component
→ selected category ID
→ form state
→ database

अगर existing Supabase "business_categories" table category source है तो उसी को properly reuse करें।

यदि अलग-अलग entity types के लिए categories चाहिए तो category records में type/scope रखें, जैसे:

- business
- product
- service
- job

लेकिन existing schema हो तो उसे unnecessarily replace न करें।

2. FIRST DEBUG THE REAL ROOT CAUSE

सबसे पहले inspect करें:

- Category table में data है या नहीं
- Supabase query चल रही है या नहीं
- RLS category read को रोक तो नहीं रहा
- Query गलत table/column use तो नहीं कर रही
- React Query key गलत तो नहीं है
- Hook data को empty array में fallback करके वास्तविक error छिपा तो नहीं रहा
- Category query authenticated user के लिए उपलब्ध है या नहीं
- Seed categories सही environment/project में हैं या नहीं
- Category IDs और entity types match कर रहे हैं या नहीं
- Cache stale/incorrect तो नहीं
- Category selector को data prop वास्तव में मिल रहा है या नहीं

IMPORTANT:

यदि database में categories मौजूद हैं लेकिन UI में खाली हैं तो नई categories blindly insert न करें।

पहले वास्तविक query/loading/RLS/state समस्या ठीक करें।

अगर categories database में हैं ही नहीं, तभी complete seed migration बनाएं।

15. SEARCH PROBLEM — CRITICAL

अभी user के अनुसार किसी word को type करते ही search/navigation trigger हो रहा है।

इसे ठीक करें।

Typing:

"Electrician"

करने मात्र से search screen/navigation/action execute नहीं होना चाहिए।

Search केवल इन परिस्थितियों में execute हो:

Option A

User keyboard पर Search/Enter दबाए।

Option B

User explicit:

🔎 Search

button दबाए।

Option C

User filter:

Apply Filters

दबाए।

लेकिन केवल text बदलने से navigation नहीं होना चाहिए।

Search input controlled state में रखें:

"searchText"

और submitted query अलग रखें:

"submittedSearchText"

उदाहरण:

User types:
"Elec"

→ कोई search navigation नहीं।

User types:
"Electrician"

→ कोई result navigation नहीं।

User presses Search:

→ अब search execute हो।

यदि existing app में live filtering intentionally है तो भी उसे same screen के results को filter करना चाहिए; दूसरे route पर automatically navigate नहीं करना चाहिए।

19. DATABASE/RLS

Category read access को verify करें।

Categories अगर public discovery/reference data हैं तो authenticated users के लिए उचित read access दें।

लेकिन write permission केवल authorized/admin migration/seed path में रहे।

Normal user category master table में arbitrary categories create/update/delete न कर सके।

Existing RLS/security को कमजोर न करें।
